# M-UI Fusion v1.1.0 — Rule switches and drag-and-drop priorities / Переключатели правил и приоритет

## English

This release adds on/off controls for individual Mihomo routing rules and direct priority reordering, without replacing Mihomo.

- All user-created rules other than MATCH have an **on/off switch**. Turning a rule off keeps its type, conditions, target, No-Resolve flag and position in the UI and saved settings, but excludes it from the active Mihomo rule list. Turning it back on restores the original rule.
- Existing configurations remain compatible: missing enabled means **on**, and enabling a previously disabled rule returns to the legacy representation.
- **Drag handles** and **up/down arrows** let users reorder all non-MATCH rules. Desktop mouse drag-and-drop and touch/pen pointer interactions are supported; arrows also support keyboard-based movement.
- **MATCH is the permanent default fallback**: always last, never draggable, movable or deletable. Its on/off switch is visible but locked **on**; its outbound remains editable. Backend validation rejects a disabled MATCH to avoid accidental traffic leakage.
- Dropping an ordinary rule onto MATCH positions it immediately above the fallback.
- Rules generated from Basics show locked switches, because they are managed by the Basics tab.
- Disabled rules have muted styling. The two-stage Apply → Save workflow stays intact.
- Backend tests cover persistence, backwards compatibility, omission of disabled rules in active YAML, ordering and MATCH protection. Chromium desktop/mobile tests exercise switches, arrow movement, drag-and-drop and locked MATCH.
- Editor JS/CSS and translation assets use ?v=110 to bypass old browser caches.

**Deployment safety:** all existing rules remain enabled and keep their priority when upgrading; subscriptions and other services are unchanged.

## Русский

Добавлены **переключатели вкл/выкл** и **перемещение правил по приоритету**. Движок Mihomo остаётся прежним.

- У всех обычных правил есть переключатель. При выключении правило остаётся в редакторе и сохраняет тип, условия, исходящий, No-Resolve и место в списке, но исключается из активной конфигурации Mihomo. При включении прежние параметры восстанавливаются.
- Старые конфигурации полностью совместимы: отсутствие поля enabled означает, что правило включено.
- Остальные правила можно **перетаскивать за ручку ⠿**, а также перемещать кнопками **вверх/вниз**. Предусмотрены мышь на компьютере и обработка касаний; стрелки остаются вариантом для мобильного и клавиатурного управления.
- **«ВЕСЬ ОСТАЛЬНОЙ ТРАФИК» (MATCH)** всегда стоит последним. Его нельзя перетаскивать, менять тип или удалять. Переключатель виден, но постоянно включён и заблокирован — защита от непреднамеренной отправки остаточного трафика в обход выбранного маршрута. Исходящий MATCH можно редактировать.
- Если перетащить другое правило на строку MATCH, оно встанет непосредственно перед ней.
- У системных правил из раздела «Основные» переключатель показан заблокированным — управление ими осуществляется там.
- Выключенные правила приглушаются. Схема «Применить» → «Сохранить» сохраняется.
- Новые тесты Go проверяют хранение отключённых правил, совместимость прежнего JSON, исключение правил из активного YAML и постоянное присутствие MATCH. Chromium проверяет включение/выключение, вертикальный порядок, перетаскивание, стрелки и фиксированный MATCH.
- JS/CSS и перевод загружаются в браузер с ?v=110.

**Без автоматического изменения маршрутов:** при обновлении существующие правила сохраняют состояние «включено» и исходный приоритет. Подписки, ядро Mihomo, DNS, firewall, Tailscale, Keenetic и другие службы не меняются.
