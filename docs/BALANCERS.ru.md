# Балансировщики и подписки в M-UI Fusion

Начиная с версии **v0.3.3-sniffer.3**, балансировщики отделены от списка отдельных узлов.

## Где находятся

- **Outbounds** (Mihomo Settings → Outbounds): отдельные прокси-узлы, в том числе импортированные подписками. Группы здесь больше не отображаются.
- **Балансировщики**: единая вкладка для ручных групп и подписок только внутри **Mihomo Settings → Балансировщики** (отдельного пункта бокового меню нет). Здесь создаются и редактируются группы.
- **Подписки**: источники VPN-узлов, их URL, интервалы автоматического обновления и последние результаты.

## Как добавить подписки в балансировщик

1. Сначала добавьте URL в разделе **Подписки** и дождитесь успешного импорта узлов в Outbounds.
2. Перейдите в **Mihomo Settings → Балансировщики**, откройте существующую группу или нажмите **Добавить балансировщик**.
3. Для обычного ручного балансировщика нажмите **«Добавить балансировщик»**. Для новой URL-подписки нажмите **«Добавить балансировщик из подписки»**, укажите URL и название группы, загрузите серверы, примените фильтры **«Оставить только»** и **«Исключить»**, при необходимости исключите отдельные узлы и настройте интервал автообновления. Выберите тип: **URL Test** (самый быстрый доступный узел), **Fallback** (приоритет по порядку), **Load Balance** (распределение запросов) либо **Select** (ручной выбор).
4. В поле **Подписки (все узлы автоматически)** выберите **один или несколько источников**. Можно одновременно оставить выбранные вручную прокси-узлы из списка Members.
5. Сохраните изменения группы и нажмите **Save** в верхней части Mihomo Settings. Перезапустите Mihomo, если панель попросит применить изменения.

Готовая группа становится обычной целью маршрутизации и доступна в **Routing Rules**. Порядок правил и текущие системные маршруты Linux не меняются автоматически.

## Автоматическая синхронизация

При очередном обновлении источника все **новые узлы** добавляются во все подключённые к нему группы. Узлы, удалённые провайдером, убираются из этих групп. Узлы других подписок и ручные участники не затрагиваются. Порядок существующих членов сохраняется; новые добавляются в порядке получения.

Если источник недоступен, пуст или изменился так, что группа останется без участников, обновление отклоняется и действующая конфигурация сохраняется. Прежде чем применять обновление, панель проверяет YAML через установленный Mihomo.

**Подписку можно подключить к нескольким балансировщикам, а в один балансировщик — несколько подписок.** Источник, подключённый ранее через поле «Балансировщик» в карточке подписки, продолжит работать; новые привязки удобнее делать в разделе «Балансировщики».

## Переход со старых версий

Существующие группы из Outbounds **не удаляются и не пересоздаются**, а только меняют место отображения. Их имена, выбранные участники, типы балансировки, параметры проверок и ссылки в Routing Rules остаются прежними.

Файлы данных продолжают храниться в защищённом state.json. Идентификаторы выбранных подписок сохраняются у каждой группы в поле subscriptionIds; в сгенерированный Mihomo YAML попадают обычные имена участников группы, без служебных метаданных.

Перед обновлением панели сохраните исходный бинарник и конфигурацию. См. [универсальную SSH-инструкцию](INSTALL.ru.md).


### Флаги и выбор серверов

В списке серверов название показывается целиком в одной строке; длинные строки можно прокручивать горизонтально или прочитать по наведению. Флаг определяется по названию сервера (явное эмодзи, двухбуквенный код либо название страны на русском/английском), а не по GeoIP.
Рядом с полями **«Оставить только»** и **«Исключить»** кнопка **«🏳️ Добавить флаг»** позволяет выбрать страну из каталога ISO 3166. Фильтры понимают флаг и название страны как эквивалентные записи — например 🇨🇭 находит узлы с названием «Швейцария». Исходное имя узла не изменяется при предпросмотре.
Интервал автообновления для новых подписок по умолчанию **1440 минут (24 часа)**. Ранее настроенные интервалы остаются без изменений.


### Отображение флагов в Windows

Флаги серверов и стран в фильтрах отображаются **локальными SVG-изображениями** (каталог ISO 3166). Это не зависит от шрифтов Windows и не требует загрузки с внешнего CDN. При выборе флага в «Оставить только» или «Исключить» записывается название страны (например Switzerland) и рядом отображается цветной SVG-флаг. Фильтры, сохранённые ранее с эмодзи 🇨🇭, продолжают работать и визуально распознаются как выбранная страна. Атрибуция графики: web/flags/LICENSE.txt (flag-icons, MIT).

### Редактор подписочного балансировщика (вкладка Mihomo Settings)

Нажмите значок карандаша напротив подписочного балансировщика. Вместо **Members** отображается **«Серверы подписки»**. В окне присутствуют только узлы источников, действительно связанных с этим балансировщиком, а не все Outbounds панели. Ручные балансировщики по-прежнему могут выбирать любые Outbounds.

Таблица содержит флаги из локального SVG-каталога, протокол, полное название сервера, ICMP-пинг (если хост отвечает) и HTTP-задержку через прокси по данным Mihomo. Показывается **текущий кандидат** (now) из работающего Mihomo URL Test/Fallback. Колонки сортируются, можно искать страну, название, протокол, а также показывать только online/offline.

**«Опросить серверы»** запускает до шести проверок одновременно через защищённый локальный API Mihomo. Результаты поступают постепенно (SSE), опрос можно остановить. Состояние online определяется HTTP-задержкой через VPN, не ICMP: отсутствие ответа на ping не делает VPN-сервер offline. Для регулярных проверок действует штатный url-test интервал Mihomo, задаваемый в свойствах группы.

**«Исключить недоступные»**, **«Снять все»**, **«Выбрать все»** изменяют выбор в редакторе. Нажмите **«Применить к конфигурации»**, затем **«Сохранить»** в Mihomo Settings для постоянного применения. Исключённые серверы остаются в общем списке Outbounds, но не возвращаются в этот балансировщик после очередного обновления его подписки.

В нижних вкладках **«Обновление»** и **«Фильтры»** доступны автообновление, интервал в часах/минутах, текстовые правила «Оставить только / Исключить», добавление страны с SVG-флагом, выбор конкретной подписки (если их несколько), отдельная кнопка **«Сохранить настройки подписки»**. Изменения фильтров запускают проверенный механизм повторного импорта, и при недоступном провайдере сохраняется старая конфигурация. **Важно:** после обновления состава узлов переоткройте окно, чтобы список отражал новый источник.

Ограничения: это адаптация для **Mihomo**, а не дословное копирование Xray Observatory из HydraRoute. **Пинг** — прямой ICMP к хосту, **Задержка** — проба через Mihomo. Показатели нельзя считать взаимозаменяемыми. В других группах, не связанных с подписками, старый универсальный редактор остаётся без изменений.

### Размер окна и закрытие

Редактор подписочного балансировщика ограничен шириной **888 px** (на 20% уже прежних 1110 px), при недостаточной ширине экрана адаптируется. Внутренний крестик над списком серверов убран: он лишь скрывал таблицу. Для закрытия всего диалога предусмотрен **один верхний крестик** и кнопка «Отмена» внизу.

### Раздельные вкладки балансировщиков и подписок

Внутри **Mihomo Settings**, рядом с «Балансировщики», есть вкладка **«Подписки»**. На вкладке **«Балансировщики»** показываются только обычные ручные группы с произвольными Outbounds; кнопка «Добавить балансировщик» создаёт такую группу. На вкладке **«Подписки»** отображаются только группы, созданные из источников VPN-подписок, с кнопкой «Добавить балансировщик из подписки». Ниже находятся карточки самих источников подписок для обновления, изменения фильтров и расписания.

Связь определяется либо полем subscriptionIds группы, либо значением group у сохранённой подписки (старые группы без subscriptionIds правильно распознаются). Это **только разделение списка в интерфейсе**, а не перенос и не изменение данных: обе категории остаются обычными Mihomo proxy-groups в config.yaml. Ручные и подписочные группы можно редактировать в соответствующей вкладке; при перестановке ручных групп подписочные группы не участвуют в изменении порядка. Отдельных пунктов в правом меню не создаётся.

### Полноценная таблица серверов для ручных балансировщиков

Теперь на вкладке **«Балансировщики»** при редактировании ручной группы (например FOREIGN или Russia) вместо старого списка **Members** отображается таблица **«Серверы балансировщика»**. Она показывает **только текущих выбранных участников**, а не все Outbounds панели: названия (с локальными SVG-флагами), протоколы, текущего кандидата, online/offline, пинг, задержку, сортировку и поиск. Кнопка «Опросить серверы» выполняет потоковую проверку через Mihomo только для уже сохранённых участников группы.

Для ручного добавления выхода используйте **«＋ Добавить Outbound»** — появится поисковая панель со всеми доступными Outbounds (обычные прокси, существующие группы и встроенные выходы). После выбора сервер появится в таблице, а список всех остальных Outbounds будет скрыт. Галочками можно добавлять и исключать серверы; изменения вступают в силу после «Применить к конфигурации» и «Сохранить». У несохранённых новых групп результаты опроса появляются после первого сохранения.

**Балансировщики из подписок не меняются:** видны только узлы привязанных подписок и их фильтры. Список сторонних Outbounds там не появляется.

### Текущий исходящий в таблице балансировщиков

На вкладках **«Балансировщики»** и **«Подписки»** столбец **«Текущий исходящий»** показывает фактический активный узел, выбранный работающим ядром Mihomo для группы. Значение берётся из поля now API Mihomo (URLTest, Fallback, Select) и обновляется автоматически примерно каждые 9 секунд, пока открыта вкладка. Это не результат проверки задержки и не статически выбранный первый сервер.

Кнопка тестирования задержки остаётся доступной. После успешного теста миллисекунды показываются отдельной строкой под текущим исходящим; если тест задержки не прошёл, показывается отдельное уведомление, а имя действующего исходящего **не исчезает**. Детали ошибки можно увидеть наведением курсора. У LoadBalance без единственного now отображается «Выбор для каждого соединения»; если Mihomo остановлен или группа ещё не применена, интерфейс это явно обозначает. Для обычных прокси в Outbounds всё остаётся по-прежнему: «Результат теста» показывает измеренную задержку.
